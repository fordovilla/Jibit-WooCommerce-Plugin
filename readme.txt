اتصال فروشگاه ووکامرس شما به درگاه پرداخت جیبیت (Jibit PPG).

== Description ==

این افزونه امکان اتصال فروشگاه ووکامرس به درگاه پرداخت جیبیت را با استفاده از API نسخه ۳ فراهم می‌کند.

ویژگی‌ها:
* اتصال به API رسمی Jibit PPG v3 (`https://napi.jibit.ir/ppg/v3`)
* مدیریت خودکار توکن دسترسی (access token) و توکن تازه‌سازی (refresh token)
* پشتیبانی از چک‌اوت کلاسیک و چک‌اوت بلوکی (Cart & Checkout Blocks)
* پیام‌های موفقیت/شکست قابل تنظیم با شورت‌کد
* اعتبارسنجی مرجع تراکنش هنگام بازگشت از درگاه برای جلوگیری از تقلب
* کسر کارمزد از خریدار (اختیاری): با روشن کردن این گزینه، افزونه با استفاده از API استعلام کارمزد جیبیت (`/v3/purchases/fee`) کارمزد تراکنش را محاسبه کرده، آن را به عنوان ردیف قابل تنظیم (پیش‌فرض «کارمزد خدمات») به مبلغ سفارش اضافه می‌کند و همان مبلغ را به عنوان wage هنگام ایجاد تراکنش به جیبیت ارسال می‌نماید.
* بازآشتی خودکار (Reconciliation): هر ۱۵ دقیقه، سفارش‌های در انتظار پرداخت که پاسخ درگاه به آن‌ها نرسیده را با استفاده از API فیلتر تراکنش‌ها (`/v3/purchases`) بررسی و در صورت موفق بودن پرداخت، سفارش را به‌صورت خودکار تکمیل می‌کند. همچنین یک اکشن دستی «بررسی وضعیت پرداخت در جیبیت» در صفحه ویرایش سفارش برای بررسی فوری اضافه شده است.
* اطلاع‌رسانی پیامکی پس از پرداخت موفق (اختیاری، از طریق سرویس جیبیت پالس با کلید API/Secret مجزا از درگاه پرداخت): ارسال پیامک به خریدار و/یا چند شماره مدیر فروشگاه، با جلوگیری از ارسال تکراری برای یک سفارش.

این افزونه فاقد قابلیت استرداد وجه (Refund) یا لغو تراکنش (Reverse) از پیشخوان ووکامرس است. برای استرداد وجه به مشتریان، از پنل کاربری جیبیت (dashboard.jibit.ir) به‌صورت مستقیم اقدام نمایید.

== Installation ==

1. افزونه را در مسیر `wp-content/plugins/` آپلود و فعال کنید.
2. به مسیر ووکامرس > تنظیمات > پرداخت‌ها > جیبیت بروید.
3. کلید API و کلید مخفی دریافتی از پنل جیبیت (dashboard.jibit.ir) را وارد کنید.
4. درگاه را فعال و تنظیمات مورد نظر را ذخیره کنید.

== Changelog ==

= 1.7.3 =
* فیلد description ارسالی به جیبیت اکنون فقط و فقط نام و نام خانوادگی خریدار است، بدون هیچ کاراکتر یا برچسب اضافه.

= 1.7.2 =
* در تلاش اول پرداخت، clientReferenceNumber دقیقاً برابر شماره سفارش ووکامرس است (بدون هیچ پسوندی) تا جست‌وجوی دقیق (exact match) شماره سفارش در پنل جیبیت نتیجه بدهد. فقط در صورت تلاش مجدد پس از پرداخت ناموفق، پسوند شماره تلاش (مثلاً «-2») اضافه می‌شود.

= 1.7.1 =
* شماره تراکنش نمایش‌داده‌شده در پنل جیبیت (clientReferenceNumber) اکنون با شماره سفارش ووکامرس شروع می‌شود (قابل جست‌وجو برای پذیرنده)؛ رشته «wc-» و نام خریدار به فیلد توضیحات (description) منتقل شدند.

= 1.7.0 =
* افزودن گزینه مستقل «ارسال پیامک به خریدار» تا بتوانید بدون خاموش کردن کل سیستم پیامکی، فقط پیامک خریدار را غیرفعال کنید (پیامک مدیر مستقل از این گزینه ارسال می‌شود).
* پیامک خریدار سازمان‌یافته‌تر شد: نام فروشگاه، متن پیام، تشکر و تاریخ/ساعت شمسی هرکدام در خط جداگانه.
* واحد پول در متن پیامک‌ها از IRR به «ریال» تغییر کرد.

= 1.6.1 =
* متن پیامک مدیر بازنویسی شد: شامل نام فروشگاه، مبلغ، شماره تراکنش، شماره سفارش و تاریخ/ساعت به تقویم شمسی.

= 1.6.0 =
* افزودن اطلاع‌رسانی پیامکی پس از پرداخت موفق از طریق سرویس جیبیت پالس (Pulse SMS API)، با تنظیمات مجزا برای فعالسازی، کلید API/Secret، شماره ارسال‌کننده و شماره(های) موبایل مدیر. پیامک به خریدار و مدیر فروشگاه ارسال می‌شود و برای هر سفارش حداکثر یک‌بار (idempotent) ارسال می‌گردد.

= 1.5.1 =
* افزودن نرمال‌سازی شماره موبایل خریدار: فرمت‌های +989xxxxxxxxx، 0098xxxxxxxxxx و 98xxxxxxxxx پیش از ارسال به جیبیت به فرمت محلی 09xxxxxxxxx تبدیل می‌شوند. پیش از این، جیبیت این فرمت‌ها را با خطای payerMobileNumber.is_invalid رد می‌کرد.

= 1.5.0 =
* حذف کامل مکانیزم لغو تراکنش (Reverse Transaction) و استرداد وجه از افزونه. رفتار Reverse مستندسازی‌نشده و غیرقابل‌اتکا بود؛ استرداد اکنون باید مستقیماً از پنل جیبیت انجام شود.
* حذف پشتیبانی 'refunds' از درگاه، بنابراین دکمه استرداد در سفارش‌های ووکامرس دیگر نمایش داده نمی‌شود.

= 1.4.0 =
* حذف کامل استفاده از Refund Purchase API. استرداد از پیشخوان ووکامرس اکنون منحصراً از طریق API لغو تراکنش (Reverse) انجام می‌شود؛ در صورت عدم امکان لغو، به‌جای فراخوانی استرداد وجه واقعی، خطای مربوطه نمایش داده می‌شود.
* استرداد جزئی دیگر پشتیبانی نمی‌شود (چون Reverse فقط لغو کامل را پشتیبانی می‌کند)؛ تلاش برای استرداد مبلغی کمتر از کل سفارش با پیام خطای واضح رد می‌شود.

= 1.3.0 =
* افزودن فیلد قابل ویرایش «عنوان ردیف کارمزد» (پیش‌فرض: «کارمزد خدمات») برای حالت کسر کارمزد از خریدار.
* تغییر عبارت لغو تراکنش در یادداشت‌های سفارش به «لغو تراکنش (Reverse Transaction)» برای تمایز روشن از استرداد وجه (Refund).

= 1.2.1 =
* عنوان و توضیحات درگاه دیگر توسط پذیرنده قابل تغییر نیستند (مقادیر ثابت شدند).
* تغییر نام ردیف کارمزد از «هزینه خدمات» به «کارمزد خدمات».

= 1.2.0 =
* افزودن بازآشتی خودکار سفارش‌های در انتظار پرداخت با API فیلتر تراکنش‌ها (هر ۱۵ دقیقه) به همراه اکشن دستی بررسی وضعیت در صفحه سفارش.
* استفاده از API لغو تراکنش (Reverse) به‌عنوان روش سریع‌تر استرداد کامل، پیش از رجوع به استرداد معمولی.
